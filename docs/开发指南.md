# 开发指南

更新时间：2026-06-20

## 1. 技术环境

| 组件 | 当前要求 |
| --- | --- |
| JDK | 17 |
| Spring Boot | 3.3.5 |
| Maven | 3.9+ |
| Node.js | `^20.19.0` 或 `>=22.12.0` |
| MySQL | 8.x |
| Redis | 5.0+ |
| 前端 | Vue 3、TypeScript、Vite、Ant Design Vue、Pinia、Axios |
| AI | ONNX Runtime 1.18.0 |
| 排产优化 | OR-Tools 9.12 CP-SAT |

## 2. 项目目录

```text
saas/
├─ backend/                         Spring Boot 后端
│  └─ src/main/java/com/zhihuitong
│     ├─ modules/                   业务模块
│     ├─ security/                  JWT、Redis 会话、权限与数据范围
│     └─ common/                    响应、异常、分页等公共能力
├─ frontend/                        Vue 前端
│  └─ src
│     ├─ api/                       请求封装
│     ├─ views/                     页面
│     ├─ router/                    路由与菜单
│     ├─ stores/                    登录状态
│     └─ directives/                按钮权限
├─ docs/                            当前开发文档、SQL 和 ONNX 模型
└─ photo/
   ├─ upload/                       原始质检图片
   └─ results/                      AI 结果图片
```

## 3. 数据库初始化

1. 创建数据库：

```sql
CREATE DATABASE zhihuitong CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 按顺序导入：

```text
docs/zhihuitong.sql
docs/auth_schema.sql
docs/data_scope_migration.sql
```

3. 初始化脚本提供管理员账号，部署后必须立即修改初始密码。具体账号策略见 [权限与认证](./权限与认证.md)。

当前未引入 Flyway 或 Liquibase，表结构变更必须同步维护 SQL 文件。

## 4. 启动命令

### 后端

```powershell
mvn -f backend/pom.xml spring-boot:run
```

默认地址：`http://localhost:8080`。

健康检查：

```text
GET http://localhost:8080/actuator/health
```

### 前端

```powershell
Set-Location frontend
npm install
npm run dev
```

默认开发地址通常为 `http://localhost:5173`。前端通过 `/prod-api` 代理访问后端。

## 5. 构建与测试

```powershell
mvn -f backend/pom.xml test
Set-Location frontend
npm run build
```

前端还提供：

| 命令 | 作用 |
| --- | --- |
| `npm run type-check` | Vue/TypeScript 类型检查 |
| `npm run build-only` | 仅执行 Vite 构建 |
| `npm run preview` | 预览生产构建 |
| `npm run format` | 格式化 `src/` |

项目当前没有仓库内独立的前端单元测试或 Playwright 命令，关键页面需按 [测试指南](./测试指南.md) 做浏览器回归。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |

| `JWT_SECRET` | 开发默认值 | 生产必须设置至少 32 字节的独立密钥 |
| `JWT_EXPIRE_MINUTES` | `30` | 会话有效期 |

| `CAPTCHA_ENABLED` | `true` | 是否启用验证码 |
| `CAPTCHA_EXPIRE_MINUTES` | `5` | 验证码有效期 |
| `DEEPSEEK_ENABLED` | `true` | 是否启用大模型解释 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek OpenAI 兼容接口地址 |

## 7. 关键配置

配置文件：

- `backend/src/main/resources/application.yml`
- `backend/src/main/resources/application-dev.yml`
- `frontend/vite.config.ts`

需要随部署环境调整的本地绝对路径：

```yaml
inspection.storage.upload-root
inspection.storage.result-root
ai.yolo.model-path
```

当前模型默认位于 `docs/best.onnx`，图片位于 `photo/upload` 和 `photo/results`。

主要 AI 参数：

| 配置 | 当前默认值 |
| --- | --- |
| `ai.yolo.conf-threshold` | `0.5` |
| `ai.yolo.iou-threshold` | `0.45` |
| `ai.yolo.video-conf-threshold` | `0.25` |
| `qc.stream.frame-sample-interval-ms` | `250` |
| `qc.stream.session-idle-timeout-ms` | `300000` |
| `qc.stream.max-frame-size-bytes` | `5242880` |
| `ai.deepseek.model` | `deepseek-v4-flash` |
| `ai.deepseek.max-tokens` | `1200` |

DeepSeek 只用于解释排产指标和生成质检分析报告。机台选择、时间约束和方案求解由业务规则与 OR-Tools 完成；未配置 API Key 或模型调用失败时，接口仍返回规则生成的降级报告。

生产环境使用 `application-prod.yml`。Docker 后端至少需要提供：

```text
SPRING_PROFILES_ACTIVE=prod
SERVER_PORT=8081
MYSQL_PASSWORD=***
JWT_SECRET=至少 32 字节的独立随机密钥
DEEPSEEK_API_KEY=***
```

生产配置默认使用 `host.docker.internal:3306`、`saas-redis:6379`、
`/app/docs/best.onnx`、`/app/data/upload` 和 `/app/data/results`。

## 8. 开发约束

- API ID 为 `Long`，前端按字符串处理，避免 JavaScript 精度丢失。
- 时间格式统一为 `yyyy-MM-dd HH:mm:ss`，时区为 `Asia/Shanghai`。
- 普通 API 使用 Bearer Token；只有 `/photo/**` 和 `/ws/**` 允许 query token。
- 新增业务数据隔离时，实体需包含 `deptId` 和 `createdBy`，查询必须应用 `DataScopeService`。
- 权限变更、停用、改密、重置密码后必须使 Redis 会话立即失效。
- 登录审计是旁路能力，写入失败不得阻断登录。
- 不要在日志中记录明文密码、验证码或完整 token。
