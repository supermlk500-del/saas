# zhihuitong 数据库设计说明

## 1. 修正说明

本说明以真实数据库文件元数据为准，而不是以旧版 `zhihuitong_db.sql` 文本为准。

本次修正依据：

- 真实库目录：`C:\Program Files\MySQL\MySQL Server 8.0\data\zhihuitong`
- 提取工具：`ibd2sdi`
- MySQL 配置项：`lower_case_table_names=1`

因此，真实数据库的关键特征如下：

- 数据库名：`zhihuitong`
- 表名：全部为小写，且不带下划线
- 字段名：保留 camelCase 命名
- 约束名：MySQL 自动生成的小写外键名，如 `planstep_ibfk_1`

这也是为什么旧脚本里写的是 `batchInfo`、`processRoute` 这一类名称，而你实际库里看到的是 `batchinfo`、`processroute`。

## 2. 核心结论

真实库并不是“字段结构错了”，而是“落库后的对象命名形态”和原脚本表达不一致”。

具体来说：

1. 表名被 MySQL 在当前实例下统一转成了小写。
2. 字段名仍然是原始 camelCase，并没有被改成下划线。
3. 外键关系与原始设计基本一致。
4. `qcrecord` 表真实存在扩展字段：`inspectType`、`cameraId`、`frameTime`、`imageUrl`、`confidenceScore`。

## 3. 命名规范

建议后续开发文档统一采用以下规则描述数据库：

- 库名使用：`zhihuitong`
- 表名使用真实表名：`batchinfo`、`productionplan`、`qcrecord`
- 字段名使用真实字段名：`batchId`、`planStepId`、`inspectTime`
- 若需要写概念模型，可在括号中补充中文含义，而不要再混用 `batchInfo` 与 `batch_info`

## 4. 业务域划分

14 张核心表可分为 4 组：

1. 基础主数据
- `batchinfo`
- `processroute`
- `processstep`
- `machine`
- `qcitem`
- `qccamera`

2. 工艺与设备关系
- `routestep`
- `stepmachinecapability`

3. 排产执行主链路
- `productionplan`
- `planstep`
- `processparameter`

4. 质量与异常
- `qcrecord`
- `inspectiondata`
- `exceptionrecord`

## 5. 主业务关系

主业务链路如下：

`batchinfo -> productionplan -> planstep -> qcrecord / processparameter / exceptionrecord`

基础约束链如下：

- `processroute -> routestep -> processstep`
- `processstep -> stepmachinecapability -> machine`

质量证据链如下：

- `qcitem -> qcrecord`
- `qcrecord -> inspectiondata`
- `qccamera -> inspectiondata`

## 6. 逐表设计

### 6.1 batchinfo

用途：来料批次基础信息。

字段：

- `batchId`：主键，批次 ID
- `batchNo`：唯一键，批次编号
- `supplier`：供应商
- `inDate`：入厂时间
- `weight`：重量
- `width`：门幅
- `composition`：成分
- `note`：备注

### 6.2 processroute

用途：工艺路线主表。

字段：

- `routeId`：主键
- `routeName`：路线名称
- `description`：描述
- `isActive`：是否启用
- `createTime`：创建时间

### 6.3 processstep

用途：标准工序定义。

字段：

- `stepId`：主键
- `stepCode`：工序编码
- `stepName`：工序名称
- `stepType`：工序类型
- `sortOrder`：排序号
- `defaultHours`：默认工时
- `description`：描述
- `isActive`：是否启用

### 6.4 machine

用途：设备台账。

字段：

- `machineId`：主键
- `machineCode`：唯一键，设备编码
- `machineName`：设备名称
- `machineType`：设备类型
- `description`：描述
- `status`：状态
- `createTime`：创建时间

### 6.5 qcitem

用途：质检项目标准表。

字段：

- `qcItemId`：主键
- `qcItemCode`：唯一键，质检项编码
- `qcItemName`：质检项名称
- `qcType`：质检类型
- `unit`：单位
- `standardMin`：标准下限
- `standardMax`：标准上限
- `isActive`：是否启用
- `description`：说明

### 6.6 qccamera

用途：质检摄像设备台账。

字段：

- `cameraId`：主键
- `cameraCode`：唯一键，摄像头编码
- `cameraName`：摄像头名称
- `cameraType`：摄像头类型
- `ipAddress`：IP 地址
- `location`：安装位置
- `status`：状态
- `remark`：备注

补充建议：

- 第一阶段应先登记一条本机视频源记录，用于实时视频流质检页面调用电脑摄像头
- 建议示例：
  - `cameraCode=LOCAL_CAM_001`
  - `cameraName=电脑摄像头`
  - `cameraType=local_webcam`
  - `location=质检工作站本机`

### 6.7 routestep

用途：工艺路线与工序的关联关系。

字段：

- `routeStepId`：主键
- `routeId`：外键，关联 `processroute.routeId`
- `stepId`：外键，关联 `processstep.stepId`
- `sortOrder`：工序顺序
- `isMandatory`：是否必选

### 6.8 stepmachinecapability

用途：工序与设备能力约束关系。

字段：

- `capId`：主键
- `stepId`：外键，关联 `processstep.stepId`
- `machineId`：外键，关联 `machine.machineId`
- `minWidth`：最小门幅
- `maxWidth`：最大门幅
- `maxSpeed`：最大速度
- `maxBatchWeight`：最大批次重量
- `isActive`：是否启用

### 6.9 productionplan

用途：生产计划主表。

字段：

- `planId`：主键
- `batchId`：外键，关联 `batchinfo.batchId`
- `routeId`：外键，关联 `processroute.routeId`
- `planStartTime`：计划开始时间
- `planEndTime`：计划结束时间
- `status`：状态
- `createTime`：创建时间
- `remark`：备注

### 6.10 planstep

用途：工序级排产计划表，是排产执行的核心表。

字段：

- `planStepId`：主键
- `planId`：外键，关联 `productionplan.planId`
- `stepId`：外键，关联 `processstep.stepId`
- `machineId`：外键，关联 `machine.machineId`
- `planStartTime`：计划开始时间
- `planEndTime`：计划结束时间
- `planHours`：计划工时
- `sequenceNo`：序号
- `status`：状态
- `remark`：备注

### 6.11 processparameter

用途：工序过程参数记录。

字段：

- `paramId`：主键
- `planStepId`：外键，关联 `planstep.planStepId`
- `paramName`：参数名
- `paramValue`：参数值
- `unit`：单位
- `paramType`：参数类型
- `recordTime`：记录时间
- `remark`：备注

### 6.12 qcrecord

用途：质检结果主记录表。

字段：

- `inspectionId`：主键
- `planStepId`：外键，关联 `planstep.planStepId`
- `qcItemId`：外键，关联 `qcitem.qcItemId`
- `inspectTime`：检验时间
- `inspectType`：检验方式，真实库为 `enum('offline','video')`
- `cameraId`：摄像头 ID，当前真实库有该字段，但未单独设外键
- `frameTime`：视频流中的关键帧时间
- `imageUrl`：图像地址，建议保存为 Java 内部 ONNX 推理生成的结果图相对路径，如 `photo/results/20260523/result_001.jpg`
- `confidenceScore`：识别置信度
- `resultValue`：结果值
- `resultJudge`：判定结果
- `inspector`：检验人
- `remark`：备注

说明：

- 这是当前真实库里最容易被旧文档漏写的一张表。
- `offline` 建议明确用于“图片离线质检”模式。
- `video` 建议明确用于“实时视频流质检”模式。
- `video` 模式下建议只对关键帧、异常帧或人工确认帧落库，而不是对连续视频流的每一帧落库。
- 若系统后续强化视频质检，这张表将是算法输出与人工复核的关键连接点。

### 6.13 inspectiondata

用途：质检附件与采集文件表。

字段：

- `dataId`：主键
- `qcRecordId`：外键，关联 `qcrecord.inspectionId`
- `cameraId`：外键，关联 `qccamera.cameraId`
- `fileType`：文件类型
- `filePath`：文件路径，建议保存为工作区相对路径，如 `photo/upload/20260523/source_001.jpg`
- `fileName`：文件名
- `captureTime`：采集时间
- `resultSummary`：结果摘要
- `remark`：备注

### 6.14 exceptionrecord

用途：工序异常记录表。

字段：

- `exceptionId`：主键
- `planStepId`：外键，关联 `planstep.planStepId`
- `exceptionType`：异常类型
- `exceptionLevel`：异常等级
- `description`：异常描述
- `handleResult`：处理结果
- `createTime`：创建时间
- `status`：状态

## 7. 对开发文档的影响

后续所有开发文档都应基于以下事实修正：

1. 表名统一以真实库名书写，不再使用驼峰表名。
2. 旧版表关系图如果继续使用，需要按真实表名重绘。
3. `qcrecord` 的视频质检字段应纳入详细设计与接口设计。
4. 当前数据库只覆盖排产质检核心域，不覆盖前端全部模块。

## 8. 对后续开发的建议

建议后续先做三件事：

1. 把所有后端实体类与 Mapper 表名映射统一到真实表名。
2. 补一份数据库 E-R 图，以当前真实库为准重绘。
3. 为订单、追溯、系统管理等前端模块补充数据库设计，而不是继续复用这 14 张表硬撑全部业务。
