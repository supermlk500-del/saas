## 需求概述

在现有“织慧通”代码和设计文档基础上继续完善项目。优先保证订单、批次、工艺、排产、质检、异常这条主业务链路真实可运行、文档与代码一致，并逐步补齐工程化、安全性和未接入模块。

## 功能需求

### P0 - 必须实现

- [ ] 主链路可用：订单、订单明细、批次分配、生产计划、工序计划、质检记录和异常闭环能够连续操作。
- [ ] 前后端一致：前端调用的核心接口与 Spring Boot Controller、DTO、VO 保持一致。
- [ ] 初始化可靠：新环境仅根据仓库内真实存在的 SQL 和配置即可启动。
- [ ] 质量门禁：前端生产构建、TypeScript 类型检查和后端自动化测试持续通过。
- [ ] 文档可信：README、联调说明和代码核对报告不得引用不存在的文件或过期接口。

### P1 - 重要功能

- [ ] 数据库迁移：引入 Flyway 或 Liquibase，替代手工维护整库 SQL 的升级方式。
- [ ] 权限安全：实现登录、鉴权和角色权限，保护业务写接口及质检文件访问。
- [ ] 自动化验收：补充订单到质检异常闭环的集成测试。
- [ ] 部署能力：提供环境变量模板、生产配置和可重复部署方案。
- [ ] 性能优化：拆分前端超大公共包，并验证实时质检吞吐和资源释放。

### P2 - 可选功能

- [ ] 将执行、追溯、系统管理等占位页面按业务优先级逐步接入真实后端。
- [ ] 增强实时质检的延迟平滑、最新帧策略和目标跟踪。
- [ ] 完善监控、审计日志和运行指标。

## 非功能需求

- 性能：常规列表分页查询稳定；前端首屏资源避免单包过大；实时质检不积压历史帧。
- 安全：生产环境不得依赖仓库中的默认口令；写接口需要鉴权；上传文件需限制类型和大小。
- 可用性：关键状态流转应有明确错误提示，配置和存储目录在启动时可校验。
- 可维护性：代码、SQL、接口文档和 README 使用同一套事实口径。

## 边界与约束

- 本轮不覆盖或回退用户现有未提交修改。
- 当前技术栈保持 Vue 3、TypeScript、Spring Boot、MyBatis-Plus、MySQL 和 ONNX Runtime。
- `docs/zhihuitong.sql` 是当前数据库基线；仓库中不存在独立的 `order_schema_upgrade.sql`。
- 执行、追溯和系统管理中的占位功能不视为当前主链路已实现能力。

## 验收标准

### 构建与测试

- Given 当前工作区依赖已安装，When 执行 `npm run build`，Then 类型检查和生产构建成功。
- Given Maven 与 JDK 17 可用，When 执行 `mvn test`，Then 后端测试全部通过。

### 文档一致性

- Given 新开发者只阅读 README，When 初始化数据库和启动项目，Then 不会遇到 README 引用但仓库不存在的文件。
- Given 开发者阅读质检联调文档，When 对照前端 API，Then 检测接口路径与真实代码一致。

### 主业务链路

- Given 已有订单、来料、路线、工序和设备数据，When 创建并执行生产计划、提交质检，Then 系统能形成计划、工序、质检记录及必要的异常记录。
