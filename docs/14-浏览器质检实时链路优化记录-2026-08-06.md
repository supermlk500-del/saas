# 浏览器质检实时链路优化记录（2026-08-06）

## 结论

本次优化把实时质检拆成两个互不阻塞的链路：

```text
摄像头帧
  -> 浏览器主线程采集
  -> BrowserInferenceClient
  -> Web Worker / ONNX Runtime Web
  -> 结果框绘制与页面状态更新
  -> 立即调度下一帧

连续缺陷事件
  -> 复制证据画布
  -> 有界异步上传队列
  -> 后端校验模型 SHA、类别、坐标和图片
  -> 保存原图、结果图、质检记录和附件
```

实时帧不再通过 WebSocket 或普通 HTTP 上传到后端做推理。后端不运行 ONNX，只负责业务权限、结果校验、文件保存、幂等和数据库事务。

## 前端改动

- `frontend/src/inference/browserInferenceClient.ts` 使用全局 Worker 和单个 Session；正常停止只停止帧循环，不销毁 Worker，页面卸载或模型切换时才释放。
- `frontend/src/views/quality/RealtimeInspect.vue` 使用 `requestAnimationFrame` + 单帧背压调度，摄像头直接生成缩放后的 `ImageBitmap` 交给 Worker，普通帧不经过主线程 Canvas；上传、详情查询和最近记录刷新不再阻塞下一帧。
- `frontend/src/inference/evidenceUploadQueue.ts` 提供并发上限、待处理上限、重试、事件 ID 去重、停止排空和队列状态快照。
- 正常帧只更新叠加层；只有连续缺陷命中事件才从当前视频帧生成 JPEG 证据并入队。

## 后端改动

- 删除 Java `OnnxYoloService`、ONNX Runtime Maven 依赖、实时 WebSocket 帧处理和同步快照接口。
- `BrowserInferenceModelService` 只读取静态模型清单、校验模型大小/SHA-256 并提供模型文件下载。
- `InspectionIntegrationService` 只接受浏览器结果，重新校验模型版本、类别、坐标和证据图片，然后写入质检业务数据。
- `QcStreamSessionService` 保留短期业务会话和按 `eventId` 的会话内幂等，移除帧推理状态。
- `ClientRealtimeEventRequest.frameTime` 用于保存浏览器采集时间，而不是以后端收到时间替代。

## 当前接口

| 用途 | 接口 |
| --- | --- |
| 获取模型清单 | `GET /api/ai/browser-inference/manifest` |
| 下载模型 | `GET /api/ai/browser-inference/model?sha256={sha256}` |
| 保存图片检测结果 | `POST /api/qc-records/client-detect-results` |
| 创建实时业务会话 | `POST /api/qc-stream-sessions` |
| 保存连续缺陷证据 | `POST /api/qc-stream-sessions/{sessionId}/client-events` |
| 关闭实时业务会话 | `POST /api/qc-stream-sessions/{sessionId}/close` |

## 性能观测

页面应同时观察：

- 推理阶段耗时：预处理、推理、后处理和单帧延迟；
- 推理调度：是否有帧被跳过，是否出现 Worker 错误；
- 证据队列：queued、uploading、succeeded、failed、dropped；
- 后端保存：保存失败原因和重试结果。

保存延迟升高时，不能通过提高上传并发来掩盖问题。优先确认实时推理是否仍然流畅，再检查后端文件存储、数据库和网络。
