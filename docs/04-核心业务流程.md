# 04 核心业务流程

## 主业务链路

```text
订单
  -> 订单明细
  -> 订单批次分配
  -> 来料批次
  -> 工艺路线
  -> 工序设备能力
  -> 生产计划
  -> 工序计划
  -> IQC/过程质检
  -> 异常闭环/返工/CAPA
```

## 订单到排产

1. 创建订单和订单明细。
2. 将来料批次分配给订单明细。
3. 进入订单排产池。
4. 选择批次、工艺路线和计划开始时间。
5. 后端生成 `productionplan`。
6. 根据工艺路线拆分 `planstep`。
7. 根据 `stepmachinecapability` 为工序筛选可用设备。
8. 每个工序计划绑定设备、开始结束时间、工时和状态。

## 排产核心对象

| 对象 | 说明 |
| --- | --- |
| 订单 | 需求来源 |
| 订单明细 | 具体产品、规格、颜色、数量 |
| 批次 | 可生产资源 |
| 工艺路线 | 生产步骤模板 |
| 设备能力 | 某工序可在哪些设备上执行 |
| 生产计划 | 某批次/订单的一次完整生产安排 |
| 工序计划 | 生产计划拆分出的每一道工序 |

生产计划创建前，需要在工艺中心的“设备能力”页面为工序和设备建立关系，并设置门幅、速度和最大批次重量等约束。订单排产池会根据这些关系生成推荐设备；没有满足条件的能力关系时，订单会显示为暂不可排产。

## 质检流程

### 离线图片检测

1. 前端上传图片。
2. 浏览器全局推理客户端下载并校验当前 ONNX 模型。
3. Web Worker 使用 WebGPU/WASM 完成预处理、推理和后处理。
4. 前端生成检测框和结果图。
5. 后端校验模型 SHA、类别、坐标、图片尺寸后写入 `qcrecord` 和 `inspectiondata`。
6. 前端展示结果、图片和附件。

### 实时视频检测

1. 前端打开摄像头。
2. 创建质检流会话。
3. 浏览器按固定间隔把 `ImageBitmap` 发送到同一个推理 Worker。
4. Worker 串行推理，前端实时绘制检测框；普通视频帧不上传后端。
5. 连续多帧命中缺陷后生成唯一 `eventId`，上传原图、结果图和结构化检测结果。
6. 后端幂等校验并保存关键帧和正式质检记录。
7. 停止检测时关闭业务会话并释放摄像头、Worker、Timer 和 Tensor。

## 异常闭环

1. 质检失败或人工登记异常。
2. 创建异常记录。
3. 处理人更新状态。
4. 必要时发起返工。
5. 处理完成后关闭异常。
6. CAPA 页面用于查看和跟踪纠正预防措施。

## AI 排产建议

1. 选择已有生产计划。
2. 后端读取计划、工序、设备能力、历史上下文。
3. 生成多套方案，例如交期优先、设备利用率优先、成本优先。
4. DeepSeek 负责生成可读解释。
5. 用户人工确认后应用方案。

注意：大模型不直接决定排产，只负责解释和报告；排产计算应优先使用规则、预测模型和 OR-Tools。
