# 实时质检移动对齐方案

## 背景

产线匀速移动时，当前实时质检画面中的检测框会跟不上布面移动速度。现有链路是：

1. 前端从摄像头视频中截取一帧。
2. 将帧压缩后通过 WebSocket 发送给后端。
3. 后端 ONNX 推理后返回 boxes。
4. 前端把 boxes 画到正在实时播放的视频画面上。

这个流程存在端到端延迟。返回的 boxes 对应的是“发送出去的旧帧”，但前端绘制时视频已经播放到“当前新帧”，所以产线稍快时就会出现框滞后。

## 根本原因

当前问题不是单一的绘制 bug，而是检测结果和显示画面没有做时间对齐。

主要延迟来源：

- 前端采样间隔：当前约 500ms 发送一帧。
- 图像压缩：当前实时帧会压缩到较小尺寸后发送。
- 后端推理耗时：ONNX 推理完成后才返回检测框。
- 网络和序列化耗时：WebSocket 传输和 JSON 解析存在延迟。
- 显示对象错位：检测框来自旧帧，但画在实时视频当前帧上。

## 方案优先级

### 方案 1：检测帧定格显示

将实时检测区域从“实时视频 + 旧 boxes 叠加”改为“检测用帧 + 对应 boxes 叠加”。

做法：

- 前端发送帧时保存该帧的预览图。
- 后端返回 boxes 后，前端把 boxes 绘制到同一张发送帧上。
- 实时视频可以保留为预览，但检测结果区域展示定格帧。

优点：

- 检测框与图像天然对齐。
- 实现成本低。
- 不依赖产线速度配置。

缺点：

- 视觉上不是连续实时画面，而是检测帧刷新。

适用结论：

这是当前最稳的短期方案，优先推荐。

### 方案 2：匀速移动补偿

利用产线匀速移动特性，根据检测延迟和移动速度修正检测框位置。

需要配置：

- 移动方向：横向或纵向。
- 像素速度：px/ms 或 px/s。
- 延迟估计：当前帧发送时间到返回时间的耗时。

补偿公式：

```text
offset = speedPxPerMs * latencyMs
correctedBox = originalBox + offset
```

优点：

- 仍可在实时视频上显示框。
- 对匀速产线有效。

缺点：

- 需要标定速度。
- 相机角度、透视、布面抖动会影响精度。
- 速度变化时需要重新标定或接入编码器。

适用结论：

适合作为第二阶段增强，尤其在产线速度稳定且方向固定时。

### 方案 3：提高检测吞吐

降低端到端延迟，让 boxes 更快返回。

可优化点：

- 前端采样间隔从 500ms 降到 100-200ms。
- 适当提高实时帧尺寸和质量，避免过度压缩影响检测。
- 后端异步队列只处理最新帧，丢弃积压旧帧。
- 模型推理使用更快模型或硬件加速。
- WebSocket 返回中携带 frameId，前端只接受最新 frameId。

优点：

- 降低滞后。
- 改善整体实时性。

缺点：

- 不能彻底消除显示错位。
- 后端算力不足时会反而堆积延迟。

适用结论：

可以和方案 1 或方案 2 组合使用，但不应单独作为最终方案。

### 方案 4：跟踪算法

在两次检测之间用简单跟踪补齐中间帧位置。

可选方法：

- Kalman Filter。
- Optical Flow。
- 基于匀速模型的轻量 tracker。

优点：

- 视觉连续性较好。
- 检测频率不必特别高。

缺点：

- 实现复杂度更高。
- 遮挡、纹理弱、缺陷很小的时候容易漂移。

适用结论：

适合后续增强，不建议作为当前第一版修复。

## 当前建议

短期先做方案 1：

- 检测结果区域显示“发送给后端的那一帧”。
- boxes 绘制到同一帧上。
- 实时视频只作为采集预览。

中期再加方案 2：

- 设置产线方向和速度。
- 通过 `latencyMs` 做 boxes 位移补偿。
- 在设置弹窗中暴露补偿开关、方向和速度参数。

长期再考虑方案 3 和方案 4：

- 后端只处理最新帧。
- 结合硬件触发、编码器或更快推理设备，提高工业现场稳定性。

## 2026-06-15 方案 2 实施记录

已在前端实时质检页面实现“匀速移动补偿”：

- 设置入口放在实时视频源右上角的“设置”弹窗中。
- 支持启用/关闭补偿、选择移动方向、填写像素速度（px/s）。
- 前端按最近一次 WebSocket 检测响应延迟计算补偿距离。
- 绘制检测框前先在检测帧坐标系中偏移 boxes，再映射到当前视频画布。

补偿公式：

```text
offsetPx = speedPxPerSecond * latencyMs / 1000
```

方向规则：

- 向右：x1/x2 增加 offsetPx。
- 向左：x1/x2 减少 offsetPx。
- 向下：y1/y2 增加 offsetPx。
- 向上：y1/y2 减少 offsetPx。

当前默认启用补偿，但方向默认为“不补偿”、速度默认为 0，避免未标定时误偏移。现场使用时需要根据摄像头画面中的布面移动方向和实际速度标定像素速度。设置弹窗会显示最近延迟和当前补偿距离，方便边测边调。

限制说明：

- 该方案假设产线匀速、方向固定。
- 如果摄像头视角有明显透视，画面不同区域的真实像素速度可能不同，需要后续引入区域化补偿或跟踪算法。
- 如果后端推理延迟波动较大，补偿距离会跟随最近延迟抖动，后续可加入平滑窗口。
