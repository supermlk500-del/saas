# 胚布排产质检系统接口详细设计

## 1. 文档说明

本文档用于对 [方案设计.md](C:/Users/lhr/Desktop/saas/docs/方案设计.md) 第 4 章“接口设计”进行字段级展开，作为后端 Controller、DTO、VO、Mapper 和前后端联调的直接参考依据。

本文档遵循以下范围约束：

- 以当前真实数据库 14 张核心表为第一阶段接口设计基础
- 以重新设计后的 REST 风格接口为准
- 不以现有前端 `/business/**` 调用方式为兼容目标
- 对尚未落库的订单、报工、NCR、CAPA 等模块，只保留预留说明，不展开字段细节
- 本文档描述的接口默认指“前端/外部调用 Java 主后端”的正式业务接口
- 质检算法不再使用独立 Python 服务，而是由 Java 主后端内部集成 ONNX Runtime 本地推理完成

## 2. 通用规范

### 2.1 基础约定

- 接口前缀：`/api`
- 数据格式：`application/json`
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 主键类型：`long`
- 分页参数：`pageNum`、`pageSize`
- 查询参数：统一通过 query string 传递

### 2.2 响应结构

单对象响应结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

列表响应结构：

```json
{
  "code": 200,
  "msg": "success",
  "rows": [],
  "total": 0
}
```

### 2.3 通用错误码建议

| code | 含义 | 适用场景 |
| --- | --- | --- |
| 200 | success | 请求成功 |
| 400 | bad request | 参数格式错误、必填项缺失 |
| 401 | unauthorized | 未登录或令牌失效 |
| 403 | forbidden | 无权限访问 |
| 404 | not found | 资源不存在 |
| 409 | conflict | 编号重复、状态冲突、被引用不可删除 |
| 422 | unprocessable entity | 业务校验未通过 |
| 500 | internal server error | 服务器内部异常 |

### 2.4 通用字段约定

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码 |
| msg | string | 返回消息 |
| data | object | 单对象数据 |
| rows | array | 列表数据 |
| total | long | 列表总数 |

## 3. 接口范围

第一阶段重点接口：

- 批次资源
- 工艺路线与工序资源
- 生产计划与工序计划资源
- 工艺参数资源
- 设备与工序设备能力资源
- 质检项目、质检记录、质检附件资源
- 异常记录资源

第二阶段预留接口：

- 订单资源
- 工单、派工、报工资源
- NCR、CAPA、返工单资源

内部能力接口补充说明：

- 排产算法继续在 Java 主后端内实现，不新增独立 Python 排产接口
- 质检检测由 Java 主后端内部 ONNX 模块完成，前端仍通过 `qc-records`、`inspection-data` 等正式业务接口访问结果
- 当前正式检测入口已拆分为：
  - `POST /api/qc-records/detect-image`
  - `POST /api/qc-stream-sessions`
  - `WebSocket /ws/qc-stream/{sessionId}`
  - `POST /api/qc-stream-sessions/{sessionId}/snapshot`

### 4.1 批次/订单接口

#### 4.1.1 GET /api/batches

用途：分页查询批次列表。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNum | int | 否 | 页码，默认 1 |

| batchNo | string | 否 | 批次编号，模糊查询 |
| supplier | string | 否 | 供应商名称 |

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| batchId | long | 批次 ID |

| supplier | string | 供应商 |
| inDate | string | 入厂时间 |

| width | number | 门幅 |
| composition | string | 成分 |
| note | string | 备注 |
| status | string | 业务状态，建议扩展字段 |

校验规则：

- `pageNum >= 1`
- `pageSize` 建议范围 `1~200`

### 4.6 质检接口

说明：

- 本章节描述的是 Java 主后端对前端提供的正式质检业务接口
- 当质检结果来源于图片/视频算法时，Java 主后端负责内部执行 ONNX Runtime 本地推理，再将结果写入 `qcrecord`、`inspectiondata`
- 因此前端仍然不需要直接感知模型推理细节，而是继续使用本章节定义的业务接口
- 质检原始上传图片物理存储目录统一为 `C:\Users\lhr\Desktop\saas\photo\upload`
- 质检结果图物理存储目录统一为 `C:\Users\lhr\Desktop\saas\photo\results`
- 原图文件名建议使用：`source_yyyyMMddHHmmssSSS_8位随机串.jpg`
- 结果图文件名建议使用：`result_yyyyMMddHHmmssSSS_8位随机串.jpg`
- `imageUrl`、`filePath` 等字段建议保存工作区相对路径，如 `photo/upload/...`、`photo/results/...`
- 实时质检页前端交互层面应拆分为“图片离线质检”和“实时视频流质检”，而不是在一个表单里混合处理
- 页面顶部不再保留固定的链路说明提示条
