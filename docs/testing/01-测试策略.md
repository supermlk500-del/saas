# 01 测试策略

## 测试目标

从 10 年测试经验视角，本项目测试目标不是“点点页面有没有报错”，而是确认以下问题：

1. 新人能否按文档独立启动项目。
2. 主业务链路是否闭环：订单 -> 批次 -> 排产 -> 质检 -> 异常。
3. 权限、会话、验证码是否稳定。
4. AI 排产和 AI 质检是否具备可控降级。
5. 部署到服务器后，数据库、Redis、图片、模型、DeepSeek Key 是否不会因为环境差异出错。

## 测试范围

### 功能测试

- 登录、验证码、退出、在线用户。
- 用户、角色、菜单、权限。
- 订单、订单明细、订单批次分配。
- 来料批次、批次资源池。
- 工艺路线、工序、设备、设备能力。
- 生产计划、工序计划、状态流转、重排、甘特图。
- AI 智能排产建议、方案应用、历史记录。
- 实时质检、图片检测、质检记录、质检附件。
- 异常登记、状态更新、关闭、返工、CAPA。
- 看板汇总。

### 非功能测试

- 安全：JWT、权限绕过、越权访问、敏感配置泄露。
- 性能：看板、列表、甘特图、实时质检、模型推理。
- 兼容：Chrome、Edge、不同分辨率。
- 稳定性：Redis 中断、DeepSeek 超时、模型路径缺失、数据库重连。
- 可维护性：文档、接口一致性、日志可排查性。

## 测试分层

| 层级 | 目标 | 当前状态 | 建议 |
| --- | --- | --- | --- |
| 单元测试 | Service、权限、排产规则 | 后端已有部分 | 继续补质量、AI、异常模块 |
| 接口测试 | Controller + 权限 + 参数校验 | 已有少量 MockMvc | 建议补全核心接口集合 |
| 前端组件测试 | 表格、表单、权限按钮、甘特图 | 当前缺失 | 建议引入 Vitest |
| E2E 测试 | 登录到主链路闭环 | 当前缺失 | 建议引入 Playwright |
| 部署冒烟 | 服务器环境可用性 | 当前靠人工 | 建议脚本化 |

## 测试优先级

P0 必测：

- 登录验证码。
- JWT/Redis 会话。
- 生产计划生成。
- 工序计划拆分。
- 甘特图展示。
- 图片质检。
- 异常登记与关闭。
- 服务器部署后的 `/prod-api/auth/captcha`。

P1 必测：

- AI 排产方案生成和应用。
- AI 质检分析。
- 权限菜单与按钮。
- 订单详情全链路汇总。
- Redis 有密码/无密码两种模式。

P2 建议测：

- 多浏览器样式。
- 移动端或窄屏展示。
- 大批量数据列表性能。
- 网络慢、DeepSeek 慢、模型慢场景。

## 准入标准

开始系统测试前应满足：

- 后端 `mvn test` 通过。
- 前端 `npm run build` 通过。
- 数据库脚本可导入。
- Redis 可连接。
- ONNX 模型路径有效。
- 本地能完成登录。

## 准出标准

可交付给其他开发或部署前应满足：

- P0 用例 100% 通过。
- P1 用例通过率不低于 95%，未通过项有明确说明。
- 无阻断级缺陷。
- 部署文档和环境变量清单完整。
- 新增问题已记录到风险/缺陷清单。
