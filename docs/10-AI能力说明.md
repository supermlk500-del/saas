# 10 AI 能力说明

## 总体原则

本项目中的 AI 分为两类：

| 场景 | 技术 | 职责 |
| --- | --- | --- |
| 排产建议 | 规则/算法/OR-Tools + DeepSeek | 算法生成方案，大模型解释方案 |
| 质检检测 | ONNX YOLO + 异常分析 + DeepSeek | 模型识别缺陷，大模型生成质检分析 |

大模型不直接决定排产，不直接替代质检模型。

## DeepSeek 配置

配置项：

```yaml
ai:
  deepseek:
    enabled: ${DEEPSEEK_ENABLED:true}
    base-url: ${DEEPSEEK_BASE_URL:https://api.deepseek.com}
    api-key: ${DEEPSEEK_API_KEY:}
    model: ${DEEPSEEK_MODEL:deepseek-v4-flash}
```

生产环境必须通过环境变量配置：

```text
DEEPSEEK_API_KEY
DEEPSEEK_MODEL=deepseek-v4-flash
```

## AI 排产建议

入口：

```text
前端：frontend/src/views/plan/AiScheduleAdvisor.vue
后端：modules/ai/service/AiSchedulingService.java
接口：POST /api/ai/schedule/plans/{planId}/suggestions
```

输出通常包括：

- 多套候选方案；
- 工序级排产条目；
- 交期、设备利用率、成本等指标；
- DeepSeek 生成的解释文本；
- 用户确认后的应用记录。

## AI 质检分析

入口：

```text
前端：frontend/src/views/quality/AiQualityAnalysis.vue
后端：modules/ai/service/AiQualityAnalysisService.java
接口：POST /api/ai/quality/records/{inspectionId}/analysis
```

输出通常包括：

- 风险等级；
- 缺陷类型；
- 严重程度；
- 近期样本数量；
- 缺陷率；
- 分析报告。

## ONNX 质检模型

默认模型路径：

```text
docs/best.onnx
```

配置项：

```yaml
ai:
  yolo:
    enabled: ${AI_YOLO_ENABLED:true}
    model-path: ${AI_YOLO_MODEL_PATH}
    conf-threshold: ${AI_YOLO_CONF_THRESHOLD:0.5}
```

本地开发默认值在：

```text
backend/src/main/resources/application-dev.yml
```

生产默认值在：

```text
backend/src/main/resources/application-prod.yml
```

## 质检文件输出

| 文件 | 默认路径 |
| --- | --- |
| 上传原图 | `photo/upload` |
| 结果图 | `photo/results` |

生产环境建议挂载到持久化目录，例如：

```text
/opt/saas/data/upload
/opt/saas/data/results
```

## 后续扩展建议

1. 质检：完善人工复核闭环，把误报/漏报沉淀为训练集。
2. 排产：引入工时预测，替代固定默认工时。
3. 排产：增加动态重排和多方案对比。
4. 质检：做供应商、机台、班次维度的质量趋势分析。
5. 最后再增强 AI 助手，用自然语言解释排产和质检结果。
