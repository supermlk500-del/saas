# 09 认证权限与安全

## 认证机制

系统使用：

- Spring Security
- JWT
- Redis 登录会话
- 图形验证码

核心代码：

```text
backend/src/main/java/com/zhihuitong/security
backend/src/main/java/com/zhihuitong/modules/system/controller/AuthController.java
```

## 登录流程

```text
GET /auth/captcha
POST /auth/login
  -> 校验验证码
  -> 校验账号密码
  -> 创建 Redis 会话
  -> 返回 JWT
前端保存 token
后续请求携带 Authorization: Bearer <token>
```

## JWT 要求

`JWT_SECRET` 必须至少 32 字节，否则后端启动会失败。

开发示例：

```text
change-this-development-secret-to-at-least-32-bytes
```

生产环境必须使用独立强随机密钥，不要提交到 Git。

## Redis 用途

| 用途 | 说明 |
| --- | --- |
| 验证码 | 登录验证码缓存 |
| 登录会话 | token 对应会话 |
| 在线用户 | 在线状态和强退 |

如果 Redis 密码为空，`REDIS_PASSWORD` 留空；如果 Redis 配置了密码，后端和容器环境必须保持一致。

## 权限模型

基础模型：

```text
用户 -> 角色 -> 菜单/按钮权限
```

前端按钮权限使用：

```vue
<a-button v-permission="'plan:production:create'">新增</a-button>
```

后端应在需要保护的接口上使用对应权限控制。

## 数据权限

数据权限由 `DataScopeService` 处理，用于限制不同用户可访问的数据范围。涉及部门、角色范围时，新增查询应考虑是否需要接入数据权限。

## 安全注意事项

- 不要把数据库密码、Redis 密码、DeepSeek Key、JWT_SECRET 写入 Git。
- 生产环境建议开启 HTTPS。
- 生产环境验证码不要关闭。
- 登录失败、权限不足应返回统一 JSON，不返回默认 HTML 错误页。
- 文件上传只允许业务需要的类型和大小。
