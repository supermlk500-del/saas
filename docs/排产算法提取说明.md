# 排产算法提取说明

来源文件：`排产（2） (2).zip`

## 已提取落地

本次没有把 Python/FastAPI 排产服务整体并入项目，而是提取其算法层中最适合当前 Java 主后端的部分：

- `greedy_eft` 策略：优先选择预计最早完工的候选机台。
- 候选机台过滤：只在已启用且满足幅宽、批重能力的机台能力中选择。
- 速度折算工时：当机台能力配置了速度时，用 `批重 / 速度` 估算工序计划工时；缺少速度时回退工序默认工时。
- 设备状态过滤：排除停用、维修机台，优先空闲，其次运行中。
- 算法选择原因：生成 `planstep.remark`，记录策略、机台、速度和预计工时，便于排查。

落地位置：

- `backend/src/main/java/com/zhihuitong/modules/plan/algorithm/SchedulingAlgorithmService.java`
- `backend/src/main/java/com/zhihuitong/modules/plan/algorithm/ScheduleMachineAssignment.java`
- `backend/src/main/java/com/zhihuitong/modules/plan/service/ProductionPlanService.java`

## 源 ZIP 中可继续复用的算法点

后续可以分阶段继续迁移：

- 多任务排序器：`priority_first`、`edd`、`cr`，用于订单排产池批量自动排产。
- 约束框架：硬约束/软约束拆分，未分配原因和软告警输出。
- 染色换色规则：专用缸、颜色深浅、色系、洗缸时长、连续同色上限。
- KPI 输出：已分配数、未分配数、准交率、换型小时数、最大延期天数、洗缸次数。
- 实时重排：保留锁定工序，只重排未锁定任务。
- 产线补偿：针对某类机台/产线进行局部补排。

## 暂不直接搬入的部分

- Python 服务层、数据库模型、FastAPI 接口不直接迁移，当前项目排产算法继续留在 Java 主后端。
- 源 ZIP 的独立计划版本表、约束版本表和运行日志表与当前数据库结构不同，需先完成表结构设计后再迁移。
- 复杂颜色规则需要先明确当前系统中颜色、机台专用缸、换缸损耗等业务字段来源。
