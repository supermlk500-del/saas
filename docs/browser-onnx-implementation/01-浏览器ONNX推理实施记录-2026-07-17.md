## 本项目采用的落地方案

本项目适合采用“浏览器本地推理 + 后端模型分发/结果校验/业务落库”的方案：

- `best.onnx` 仍由后端受控分发，不放入前端公开目录。
- 前端通过 `BrowserInferenceClient` 全局单例下载模型，并在 Web Worker 中运行 ONNX Runtime Web。
- Worker 优先尝试 WebGPU，失败自动回退 WASM。
- 图片质检与实时质检共用同一个客户端和同一个 Worker 队列，避免同一 ONNX Session 并发 `run()`。
- 后端不信任浏览器结果，保存前校验模型 SHA、类别映射、置信度、坐标范围、图片文件和业务上下文。
- 旧 Java ONNX 推理链路曾在迁移阶段保留；当前已删除 `onnxruntime` Maven 依赖和 WebSocket 帧推理代码。

## 模型契约

当前后端启动时从 `docs/best.onnx` 自动检查并输出：

- 输入名称；
- 输出名称；
- 输入尺寸；
- SHA-256；
- 文件大小；
- 类别顺序；
- YOLO raw 解码配置。

真实模型契约已经通过 Java ONNX Runtime 和浏览器 ONNX Runtime Web 双重验证：

- 输入：`images`，float32 `[1,3,640,640]`；
- 输出：`output0`，float32 `[1,24,8400]`；
- 解码：YOLO raw / BCN / `cxcywh` / 无 objectness / 非归一化坐标；
- 类别：ONNX metadata 中的 20 类；
- SHA-256：`cd50a08d750e8001aa174ed452402abf18637ca3aef0447e8cf7f08531c60470`；
- 文件大小：10,619,142 字节。

类别顺序只允许来自 ONNX metadata。模型缺少 `names`、输入输出不是 float32、形状不支持或标签不连续时，
后端拒绝发布模型清单，不再使用猜测或硬编码的类别兜底。

## 部署要求

生产 Nginx 必须增加：

```nginx
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Embedder-Policy "require-corp" always;
add_header Cross-Origin-Resource-Policy "same-origin" always;

location ~* \.mjs$ {
    default_type application/javascript;
    try_files $uri =404;
}

location ~* \.wasm$ {
    default_type application/wasm;
    try_files $uri =404;
}
```

后端模型路径继续使用：

```bash
AI_YOLO_MODEL_PATH=/app/docs/best.onnx
```

浏览器端生产检查：

```js
window.isSecureContext
window.crossOriginIsolated
'gpu' in navigator
```

前两项建议为 `true`；最终 Provider 以页面/Worker 返回的 `WebGPU` 或 `WASM` 为准。

## 真实浏览器验收结果

使用系统 Chrome、真实 `best.onnx`、真实登录态和本地 MySQL/Redis 完成自动化 E2E：

| 场景 | 结果 |
| --- | --- |
| 模型清单、模型下载与 SHA 校验 | 通过 |
| WebGPU 实际推理 | 通过，页面显示 `WebGPU` |
| 强制 WASM 实际推理 | 通过，页面显示 `WASM` |
| 单张图片推理与结果落库 | 通过 |
| 实时本机摄像头会话 | 通过 |
| 实时运行时并发执行图片质检 | 通过，无 Session 并发和超时 |
| 停止后关闭会话、释放摄像头、Worker 和 Timer | 通过 |
| `window.isSecureContext` | `true` |
| `window.crossOriginIsolated` | `true` |

WASM 初始化曾在 ORT Worker 内启用嵌套 pthread 时阻塞。最终方案固定 WASM 单线程，
避免 Chrome Headless 和部分 WebView 的嵌套线程池死锁；支持的客户端仍优先使用 WebGPU。

真实落库验收还发现 `qcrecord.deptId/createdBy` 未填充导致 HTTP 500，现已由
`QcRecordService.create()` 从当前登录数据范围写入，并增加回归测试。
