# 07 接口说明

## 基本约定

开发环境前端请求统一走：

```text
/prod-api
```

Vite 会将其代理到：

```text
http://localhost:8080
```

后端实际接口大多以 `/api`、`/auth`、`/system` 开头。

## 认证接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/auth/captcha` | 获取验证码 |

| PUT | `/auth/password` | 修改密码 |

### 质量管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/qc-tasks` | IQC 任务 |
| GET | `/api/qc-records` | 质检记录 |
| GET | `/api/qc-records/{inspectionId}` | 质检记录详情 |
| POST | `/api/qc-records` | 新增质检记录 |
| POST | `/api/qc-records/client-detect-results` | 保存浏览器 ONNX 图片检测结果（multipart） |
| PATCH | `/api/qc-records/{inspectionId}/review` | 复核 |
| PATCH | `/api/qc-records/{inspectionId}/close` | 关闭 |
| GET | `/api/inspection-data` | 检测附件 |
| GET | `/api/qc-items` | 质检项目 |
| GET | `/api/qc-cameras` | 摄像头 |
| POST | `/api/qc-stream-sessions` | 创建实时质检会话 |
| POST | `/api/qc-stream-sessions/{sessionId}/client-events` | 幂等保存浏览器连续缺陷事件（multipart） |
| POST | `/api/qc-stream-sessions/{sessionId}/close` | 关闭实时质检会话 |

普通摄像头帧只在浏览器 Worker 内推理，不再通过 WebSocket 上传后端。旧的
`detect-image`、`detect-frame`、`snapshot` 和 `/ws/qc-stream/{sessionId}` 已删除；
实时保存只使用 `client-events`，图片保存只使用 `client-detect-results`。

## 返回结构

普通成功响应通常为：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

分页响应通常包含：

```json
{
  "code": 200,
  "msg": "查询成功",
  "rows": [],
  "total": 0
}
```
