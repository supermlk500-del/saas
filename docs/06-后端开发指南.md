# 06 后端开发指南

## 技术栈

- Spring Boot 3.3
- Spring Security
- MyBatis-Plus
- MySQL
- Redis
- ONNX 模型分发与结果校验
- OR-Tools

## 目录说明

```text
backend/src/main/java/com/zhihuitong
├── common/       # 通用返回、分页、异常、工具
├── config/       # 框架配置
├── security/     # 登录、JWT、权限、数据权限、会话
└── modules/      # 业务模块
```

业务模块内部通常按以下结构组织：

```text
controller/
dto/
entity/
mapper/
service/
vo/
```

## 新增后端功能流程

1. 确定模块归属，例如 `order`、`plan`、`quality`。
2. 新增或修改 `entity`，对应数据库表。
3. 新增 `dto` 用于请求参数。
4. 新增 `vo` 用于返回给前端。
5. 新增 `mapper` 访问数据库。
6. 在 `service` 写业务逻辑。
7. 在 `controller` 暴露接口。
8. 给接口加权限标识。
9. 补充前端 `api` 和页面调用。

## 返回格式

普通接口使用：

```text
AjaxResult
```

分页接口使用：

```text
TableDataInfo
```

异常应抛出业务异常或交给全局异常处理器，不要在 Controller 中拼散乱错误结构。

## MyBatis-Plus 约定

配置位置：

```text
backend/src/main/resources/application.yml
```

当前配置：

- `map-underscore-to-camel-case: false`
- `id-type: assign_id`
- `table-underline: false`

这意味着数据库字段和 Java 字段映射要格外注意，不能默认假设下划线自动转驼峰。

## 配置规范

敏感信息必须通过环境变量传入，不要写死在代码或配置文件里。

常用环境变量：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_HOST` | MySQL 地址 |
| `MYSQL_PORT` | MySQL 端口 |
| `MYSQL_DATABASE` | 数据库名 |
| `MYSQL_USERNAME` | 数据库账号 |
| `MYSQL_PASSWORD` | 数据库密码 |
| `REDIS_HOST` | Redis 地址 |
| `REDIS_PASSWORD` | Redis 密码，可为空 |
| `JWT_SECRET` | JWT 密钥，至少 32 字节 |
| `DEEPSEEK_API_KEY` | DeepSeek Key |
| `AI_YOLO_MODEL_PATH` | ONNX 模型路径 |

## 浏览器质检支持

质检主链路在浏览器 Web Worker 中执行 ONNX 推理。后端不接收普通视频帧做推理，主要职责是：

- 检查真实 ONNX 输入、输出和类别 metadata，并分发版本化模型；
- 校验浏览器提交的模型 SHA、类别、坐标和图片；
- 幂等保存实时缺陷事件、原图、结果图和业务记录。

核心类：

```text
modules/ai/service/BrowserInferenceModelService.java
modules/quality/service/ClientInferenceResultValidator.java
modules/quality/service/InspectionIntegrationService.java
modules/quality/service/QcStreamSessionService.java
```

后端已移除 Java ONNX Runtime、实时 WebSocket 帧推理和同步快照链路。实时页面只提交连续缺陷事件的原图、结果图和结构化结果，后端负责权限、模型版本/结果校验、文件保存和业务落库。

## 排产建议

核心类：

```text
modules/ai/service/AiSchedulingService.java

```

排产计算应使用规则、算法和 OR-Tools，大模型只用于解释。

## 设备删除规则

设备管理接口支持删除设备，但删除前必须检查关联关系：

- 如果设备已被 `stepmachinecapability` 引用，不允许删除；
- 如果设备已被 `planstep` 引用，不允许删除；
- 已被业务使用的设备应改为停用，而不是强制删除；
- 删除接口使用现有的 `process:machine:edit` 权限，前端删除按钮也受该权限控制。

删除接口：

```text
DELETE /api/machines/{machineId}
```

服务层负责关联检查和统一返回 409 冲突错误，Controller 不直接操作数据库。
