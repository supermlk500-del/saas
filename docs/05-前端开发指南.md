# 05 前端开发指南

## 技术栈

- Vue 3
- TypeScript
- Vite
- Ant Design Vue
- Pinia
- Axios

## 目录说明

```text
frontend/src
├── api/              # 接口封装
├── assets/styles/    # 全局样式
├── components/       # 通用组件
├── constants/        # 字典
├── directives/       # 权限等指令
├── hooks/            # 组合式函数
├── inference/        # ONNX Worker、预处理、后处理、渲染与队列
├── layout/           # 主布局
├── router/           # 路由和菜单
├── stores/           # Pinia
├── types/            # 类型
├── utils/            # 工具函数
└── views/            # 页面
```

## 本地命令

```bash
cd frontend
npm install
npm run dev
npm run build
npm run type-check
npm test
npm run test:e2e:onnx
```

## 新增页面流程

1. 在 `src/views/<module>/` 下新增 Vue 页面。
2. 在 `src/api/<module>/` 下新增接口封装。
3. 在 `src/types/domain.ts` 或独立类型文件中补充类型。
4. 在 `src/router/routes.ts` 注册路由。
5. 如需菜单展示，设置 `meta.showInMenu = true`。
6. 如需按钮权限，配合 `v-permission` 使用后端权限标识。

## 接口请求规范

统一通过：

```text
src/utils/request.ts
```

接口模块只负责封装路径和参数，不直接处理 UI 提示。

示例：

```ts
export const fetchPlans = (params: PlanQuery) =>
  request<TableDataInfo<ProductionPlanItem>>({
    url: '/api/production-plans',
    method: 'get',
    params,
  })
```

## 表格页面规范

常规列表优先使用：

- `TablePage.vue`
- `SearchBar.vue`
- `useTable.ts`

这样可以保持搜索、分页、loading、操作区风格统一。

## ID 展示规范

业务主键通常是雪花 ID，页面展示时不要直接显示完整长 ID。

使用：

```text
src/utils/idFormat.ts
```

约定：

- 生产计划：`formatPlanId` -> `P-xxxxx`
- 工序计划：`formatPlanStepId` -> `S-xxxxx`
- 质检记录：`formatInspectionId` -> `I-xxxxx`

完整 ID 可以放在 tooltip 中，接口参数仍使用原始 ID。

## 设备能力页面

设备能力页面路由为：

```text
/master/capability
```

页面用于维护工序和设备之间的可生产关系。工序和设备下拉选项来自现有基础数据，页面不要求用户手填长 ID。每条能力关系可以设置最小门幅、最大门幅、最大速度、最大批次重量和启用状态。

只有启用且满足订单门幅、批次重量约束的能力关系，才会参与订单排产池的设备推荐。

对应接口：

```text
GET    /api/step-machine-capabilities
POST   /api/step-machine-capabilities
PUT    /api/step-machine-capabilities/{capId}
DELETE /api/step-machine-capabilities/{capId}
```

## 图片访问

质检图片路径统一通过：

```text
src/utils/image.ts
```

不要在页面里手写 `/photo/...` 或后端绝对路径。
