# 11 测试与排错

## 前端检查

```bash
cd frontend
npm test
npm run build
npm run test:e2e:onnx
```

该命令包括：

- TypeScript 类型检查；
- ONNX 预处理、后处理、串行队列和超时单元测试；
- Vite 生产构建。

浏览器 E2E 需要后端、Vite、MySQL 和 Redis 已启动，并设置本地测试密码：

```powershell
$env:E2E_PASSWORD='你的本地测试账号密码'
npm run test:e2e:onnx

# 强制走真实 WASM 回退链路
$env:E2E_DISABLE_WEBGPU='1'
npm run test:e2e:onnx
```

## 后端检查

```bash
cd backend
mvn test
mvn package
```

## 接口连通性

后端健康检查：

```bash
curl http://localhost:8080/actuator/health
```

Prometheus 指标（无需登录）：

```bash
curl http://localhost:8080/actuator/prometheus
```

当前仅通过 HTTP 暴露 `health`、`info`、`metrics`、`prometheus`。`env`、`beans`、`heapdump` 等可能泄露敏感信息的端点不会暴露。

验证码：

```bash
curl -i http://localhost:8080/auth/captcha
```

前端代理验证码：

```bash
curl -i http://localhost:5173/prod-api/auth/captcha
```

## 常见问题

### 1. 后端启动失败：JWT secret must be at least 32 bytes

原因：`JWT_SECRET` 太短或未配置。

处理：

```text
JWT_SECRET=change-this-development-secret-to-at-least-32-bytes
```

生产环境请使用强随机密钥。

### 2. 验证码不显示

检查：

- 后端是否启动成功；
- `/auth/captcha` 是否返回 200；
- Redis 是否可连接；
- 前端代理 `/prod-api` 是否指向后端；
- 服务器 Nginx 是否能访问后端容器。

### 3. Redis 报 NOAUTH 或 WRONGPASS

检查：

- Redis 是否真的设置了密码；
- `REDIS_PASSWORD` 是否和 Redis 配置一致；
- Docker Compose 中 Redis 和后端环境变量是否一致。

如果 Redis 没有密码，后端 `REDIS_PASSWORD` 应为空。

### 4. 质检模型加载失败

检查：

- `AI_YOLO_MODEL_PATH` 是否存在；
- 容器内路径是否正确；
- 模型文件是否挂载到容器；
- `ai.yolo.enabled` 是否为 true。
- `/api/ai/browser-inference/manifest` 是否返回 200；
- 模型 metadata 中是否存在连续的类别 `names`；
- 浏览器网络面板中 `/ort/*.mjs` 和 `/ort/*.wasm` 是否返回 200。

### 5. 浏览器质检一直显示“正在创建推理会话”或“正在预热模型”

检查：

- 页面“本地推理状态”显示的具体阶段；
- Nginx 是否返回 COOP、COEP、CORP 三个隔离响应头；
- `.wasm` 是否为 `application/wasm`，`.mjs` 是否为 `application/javascript`；
- 是否误开 ORT 嵌套多线程。当前项目固定单线程 WASM，WebGPU 仍优先。
- Chrome 控制台是否出现模型 SHA 或不支持算子错误。

### 6. 质检结果图不显示

检查：

- `INSPECTION_STORAGE_UPLOAD_ROOT` 和 `INSPECTION_STORAGE_RESULT_ROOT`；
- 后端静态资源映射；
- 结果图是否真实生成；
- 前端图片 URL 是否通过 `utils/image.ts` 处理。

### 7. 前端页面 502

检查：

- 后端容器是否启动；
- 后端端口是否和 Nginx 代理一致；
- `/prod-api` 是否转发到正确服务；
- 后端日志里是否有启动异常。

### 8. DeepSeek 超时

检查：

- `DEEPSEEK_API_KEY` 是否配置；
- 服务器是否能访问 DeepSeek API；
- `DEEPSEEK_TIMEOUT_SECONDS` 是否过短；
- 后端是否有降级逻辑。
